### Task 5.5.2 — Create the WebGL Showcase Section Architecture
**Objective:** Build a new dedicated section for 3D capabilities.
**Instructions:**

2. Design a split-screen or full-width layout (depending on mobile-first responsiveness).

4. Add supporting text explaining LabXR's capability with Three.js, shaders, and 3D models.
5. Create a dedicated container for the 3D Canvas with a strict aspect ratio (e.g., 16:9 or 4:3) to prevent Cumulative Layout Shift (CLS).
6. Insert this new section into `src/pages/index.astro` immediately after the `<Hero />` section.

### Task 5.5.3 — Upgrade the WebGL Component (Models + Generative Particles)
**Objective:** Transform the old particle sphere into a robust 3D showcase capable of rendering models and generative shaders.
**Instructions:**
1. Rename/refactor `hero-webgl.tsx` to `showcase-webgl.tsx`.
2. **Mobile & Reduced Motion Check:** If `$isMobile` or `$prefersReducedMotion` is true, return `null` (or a static fallback image/CSS gradient).
3. **The Scene:** 
   - Set up a `<Canvas>` with `camera={{ position: [0, 0, 6], fov: 45 }}`.
   - Add basic lighting using `@react-three/drei` (`<Environment preset="city" />` or simple ambient/directional lights).
   - **The 3D Model Pipeline:** Create a `<ModelPlaceholder />` component. Since we do not have the final GLTF model yet, use a lightweight procedural geometry (e.g., a wireframe `TorusKnot` or `Icosahedron`) styled with a dark, metallic material. Structure this component so it can easily be swapped for `useGLTF('/models/labxr-model.glb')` in Phase 6.
   - **The Generative Particles:** Adapt the existing particle shader (`particles.vert` and `particles.frag`). Instead of a simple sphere, map the particles around the 3D model, creating a "data stream" or "constellation" effect that reacts to mouse movement.
4. **Memory Management:** Implement `useFrame` with a visibility check. Pause the animation loop if the section scrolls out of view. Dispose of all geometries and materials on unmount.

### Task 5.5.4 — Update Diagnostic Route & Performance Check
**Objective:** Ensure the new architecture is testable and performant.

## 5. WHY THIS PLAN WORKS

1. **Narrative Clarity:** The user journey becomes much cleaner. They first see the *result* (the cinematic video), and immediately below, they see the *engine* (the interactive 3D WebGL showcase). 
2. **Future-Proofing:** By building the `<ModelPlaceholder />` architecture now, when you get your actual 3D models (GLTF/GLB files) in Phase 6, the AI will only need to swap one line of code (`useGLTF`) rather than rebuilding the entire section.
3. **Performance Safety:** We are keeping the Three.js chunk isolated. Because the Hero is now just a video, the initial page load will actually be *faster*, and the heavy WebGL chunk will only load when the user scrolls down to the new showcase section.
